同一个视频（吉他《花之舞》，5分21秒），两种承载方式对比。

## 方式 A：压缩后放本站仓库（读者直连可播）

原片 131MB（3.4 Mbps），用板子的 Rockchip 硬件编码压到 **18.8MB / 640×480 / 490kbps**，放进仓库：

{{< video src="/video/huazhiwu-web.mp4" poster="/img/wswx3.jpg" >}}

- 已远低于 GitHub 单文件 100MB 上限，读者**无需代理**即可播放、可拖动进度；
- 压缩命令（板子 RK3588 硬件编码，约 30 秒）：
  `ffmpeg -i in.mp4 -c:v h264_rkmpp -b:v 420k -c:a aac -b:a 64k -movflags +faststart out.mp4`

## 方式 B：原片放家里的板子（自用 / 挂代理才可看）

{{< video src="https://lubanmao-video.tailb1cb86.ts.net/huazhiwu-20250221.mp4" >}}

## 方式 C：4K 大视频 → 仓库压缩版（音频无损）

4K 原片（1.3 GB，4分48秒）压到 **14.5MB / 720p**，音频原轨照抄：

{{< video src="/video/promise-web.mp4" poster="/img/wswx3.jpg" >}}

| 项 | 原片 | 压缩版 |
|---|---|---|
| 视频 | 3840×2160 · 38.7 Mbps | 1280×720 · ~223 kbps |
| 音频 | AAC 44.1kHz 双声道 186kbps | **AAC 44.1kHz 双声道 186kbps（原轨照抄）** |
| 大小 | 1.3 GB | 14.5 MB |

关键命令（音频无损的关键是 `-c:a copy`）：

```bash
ffmpeg -i in.mp4 -vf scale=-2:720 -c:v libx264 -crf 28 -maxrate 1.2M -bufsize 2.4M -c:a copy -movflags +faststart out.mp4
```

前提：原片音频必须是 AAC（浏览器 mp4 原生支持）才能直接 copy；若是 AC3/DTS 等浏览器不认的编码，先转 `-c:a aac -b:a 320k`（听感仍近无损）。
